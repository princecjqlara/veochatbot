# Contact access, demographics and tags

Owner and Team Leader navigation includes Contacts & Bulk Tools and Contact Tags while their landing view remains the Teams Dashboard. The Owner can open every permitted VEO Page and contact. Current Page grants still authorize profile data, demographic edits, tag definitions and tag assignments; revoked, disabled and other-tenant Pages remain blocked.

Contact profiles offer manual tag selection, Page-tag creation and removal. Tag list categories keep manual tags separate from system and stage-history tags. The assignment endpoints protect system tags, verify contact/Page and tag permissions, and surface failures instead of closing the form as if a failed update succeeded. Tagging never verifies payments or changes sales qualification.

AI demographics use only existing customer excerpts, previously grounded customer answers and new launch-period messages. This does not restart Meta historical conversation imports or the old full-profile AI worker. The extractor supports age, self-described gender, recorded location, country, region, province/state, city/municipality, industry, business subtype, occupation, job role and stated language preference. Values must occur verbatim in quoted customer evidence. Personal traits cannot come from names, Page sales pitches, photos, message language, third-person examples or stereotypes. Unsupported values remain Unknown.

New customer messages queue a bounded extraction, with a short debounce and a 15-minute interval for repeated activity. The existing authenticated contact-profile schedule handles two jobs per run. Initial enrollment includes only contacts created since launch. Older contacts can be reviewed with **Extract AI demographics**; manually requested reviews take priority. Source hashes avoid charging for unchanged text. Leases, retry backoff and version checks preserve pending updates and existing results after failures. Each extraction reads up to 24 retained excerpts; it is never labelled complete conversation history.

Manual demographic corrections are merged atomically into existing contact details and audited. Explicit manual clearing masks an older AI value. AI data is stored separately and cannot overwrite corrections, verify payments or change lead stage. Cohort reports receive only the demographic values, without source message text. Subgroups display country/province/city, industry/business subtype, occupation/job role and preferred language, with both group and cohort percentages including Unknown.

Unanswered or placeholder saved-form values can be filled by grounded AI facts. Explicit manual clearings and declined disclosures remain protected. Field aliases and source layers are normalized once during aggregation so large inquiry cohorts stay responsive.

Migration `202611070003` makes calendar Page inputs read-only. Current-day planning is prepared once before the concurrent reads; historical reports do not refresh today's planning. Salary is read directly from the authoritative daily finance function, avoiding a second full pass over legacy ad-spend reports. This prevents parallel Page requests from waiting on each other's target/capacity writes.

Apply migration `202611070002` with the workspace release script before deploying the compatible app. Run demographic/source validation, queue/permission SQL, tag API, UI and navigation tests, plus the production build. `node --env-file=.env.local scripts/verify-veo-contacts.mjs --analyze` checks production Head access on every Page, profiles, tag visibility, private demographic storage and one queued saved-source AI review. It does not modify tags, payments or messaging destinations.
