# Employee performance profiles

In **Employee Performance**, **Rankings** or **Salary**, choose an employee or click a ranking name. Owner, Team Leaders and Managers can inspect selling workers in their permitted branch. Members can see their own profile through Salary. The Page and Philippine date filters apply to the profile and order search. Performance and Rankings start with the latest 30 dates, clamped to launch. Up to 93 dates can be selected.

The profile combines identity, current Page assignments, participation today/tomorrow, capacity, completed-sale and commission averages, client outcomes, reply rates, daily attendance and rank history, and links to current and previous clients. Client lists show the latest 50, with the full count; the existing client/order search remains below the profile.

## Definitions

- **Daily capacity / quota** uses the existing target snapshot: floor(80% of the best three eligible Done Deal dates in the previous 14 completed Philippine dates), minimum 1. Fewer than three eligible dates uses 1. The displayed observed maximum is the largest recorded Done Deal count on a date since launch within permitted/selected Pages; it is not a guaranteed ceiling. Historical dates without a target snapshot explicitly show the existing default of 1.
- **Salary** reuses `veo_finance_days`, including the all-Page personal qualification rule: both CD and DD targets are needed for 40%, otherwise 35%. Page shares conserve the exact whole-day commission. Gross is completed order value before refunds, net sales reflect verified refunds, and currencies are separate. These are completion-day sales, not deposit cash flow. Corrections use the existing ledger/audit process.
- **Average daily gross / salary** divides completed employment-date totals by every eligible completed employment date in the selected range, including zero-sales dates. Today is excluded from averages and shown provisionally. Salary per declared active day is shown separately and uses only declared active completed dates. Missing attendance never means absence.
- **CD-to-DD rate** follows orders whose first verified down payment/first full payment was on a selected date. The numerator includes that same cohort's eventual verified full-payment milestone through report time, even after the selected range. The average and median use elapsed hours for completed orders in that cohort, including zero hours for immediate full payments. Pending orders are excluded from turnaround averages, not treated as zero.
- **Assigned-client conversion** follows distinct clients assigned to the worker during the selected dates. A client qualifies once when a Converted contact has a verified first payment on an order attributed to the worker during that recorded ownership interval. Later verified payments can qualify an earlier assignment cohort. Shared Page inquiries and lead-stage labels alone never create personal financial conversions. This is an assignment cohort, not the calendar's first-inquiry cohort.
- **Personal reply rate** counts observed assigned-client days with an inquiry and a manual reply attributed to the same worker within 24 hours, before the ownership interval ends. Repeated incoming messages for one client/date count once. Bot/campaign replies do not count. Unattributed Page replies are reported separately; neither Business Suite Page identity nor Page assignment establishes an employee identity. Capture start dates and open 24-hour windows are disclosed. Unrecorded ownership/replies remain unavailable.
- **Ranking history** reconstructs daily ranks from current verified CD/DD milestones against the full permitted eligible peer population before selecting the employee. Sort: DD descending, then CD descending, dense ties. Zero-sale dates are unranked. Former workers remain eligible on their recorded employment/sales dates. Audited attribution corrections can change reconstructed past ranks. A Page filter provides Page-specific history. Members have no peer-ranking access.
- **Attendance sheet** displays existing workspace/Jaucian participation declarations and their source. No time-clock or actual-hours data is inferred. A supervisor replacement of a Telegram current-day declaration is correctly recorded as a workspace declaration.

The service-only `veo_employee_profile` RPC enforces active actor, tenant, branch and current Page grants independently of the authenticated API. Legacy retained sales are excluded from new-period performance, capacity and commission. The profile does not import historical conversations, send messages, change payroll or modify Jaucian destinations.

## Release validation

Run the employee profile SQL, model, API and rendered-component tests, plus the existing operations/calendar tests and production build. Apply migrations `202611070004` through `202611070006` before deploying the caller. Client history begins with the worker's assigned/sold client IDs so unrelated shared-Page history does not expand a personal profile query. Calendar and employee profile reads use parameter-specific query plans to avoid reusing an unsuitable generic plan for another Page, branch or date range on pooled connections. `scripts/verify-veo-employee-profiles.mjs` compares live authorized profiles with the authoritative finance RPC and checks branch/Page denial, anonymous denial, function privacy and immutable launch cutoff. It never dispatches Telegram/customer messages or modifies financial/attendance records; the existing finance RPC may prepare today's target snapshot.
