# Workspace search, Deals, Owner dashboard and Telegram profile

The workspace now reads contact search results from the correct `items` response. Its own scoped contact query lists clients even when they have no new-period orders. Search covers names, client IDs and manually saved detail values across all assigned VEO pages, with optional page selection and 25-result pagination. Selecting **Use client** fills the order form with that client's actual page. Page metadata loads separately so typing does not repeat Facebook connection checks.

**Deals** replaces the two Closed Deals and Done Deals tabs in the workspace and sidebar. Its **Deal type** dropdown selects Closed or Done, retaining the server's Philippine work-date and full-ledger pagination rules. Older links to the individual deal views continue to open the corresponding dropdown selection.

CJ's Owner home is a separate **Teams dashboard**: leader/team/worker counts, branch selection, team Closed/Done results, commission totals separated by currency, tomorrow's participating workers and targets, and expandable worker results and attendance. Individual contact and sales-entry forms stay on worker views. Account creation, page grants, Telegram mappings and the archive are under **Accounts & Teams**. Settings, Collection Health and My Profile remain separate management destinations.

After authentication, each new sign-in asks the account holder to confirm their Telegram username, prefilled when available. An explicit **I do not have a Telegram username** option records that fact. The username is normalized and audited, shown in the supervisor's account directory and editable under My Profile. This self-reported username never grants a role or creates/changes the separately verified numeric Telegram delivery mapping. The save API always uses the authenticated account, regardless of supplied user IDs. Browser session refresh checks the saved database confirmation after the current login timestamp.

Facebook sign-in and connection setup are removed for all roles. CJ uses the configured Owner email/password. Old Facebook sessions are rejected, and account linking cannot grant access. Existing VEO Page tokens and signed message webhooks remain in service; Page settings show the retained connections without a Facebook login or connection button.

Migration `202611050016_veo_contacts_and_telegram_profile.sql` adds the profile metadata and the service-only contact search and profile functions. The original launch cutoff, archived records, Owner identity, page connections and verified financial history remain intact.
